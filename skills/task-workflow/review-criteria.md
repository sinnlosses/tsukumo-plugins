# レビューの観点

差分を点検する4種類の観点。受け入れ役のレビューと、最後の段の担当の自己点検が同じものを使う。指摘をこの4種類に絞る。

- 正しさ: 差分の挙動が壊れている・規約が決めた前提に反して動かない
  - 判定の形: 差分が足した判定が、文字列・正規表現・行の形（1行目・先頭語の照合を含む）・モデルの自己申告に依っていて、構造化した値・台帳・型で置き換えられる（置き換えられない例外はプロジェクトの規約のファイルに書かれたものに従う）
- 完了条件: 満たしていない・満たし方が誤っている行
- 規約: 渡した規約のファイルに書かれた規則に差分が反している（根拠の規則の場所を添える）
- 簡素化: 次の4観点のどれかに当たる
  - 再利用: 差分が新しく書いたものと同じことをする関数・部品がリポジトリに既にある（その場所を挙げる）
  - 簡素化: 同じ挙動のまま、読む人が追う分岐・状態・間接が減る書き方がある
  - 効率: 同じ計算・入出力・待ちを重ねて足している
  - 抽象の高さ: 1つの関数・ファイルの中で高い呼び出しの並びと低い詳細が混ざっている、または置いた層の責務に合っていない

規約の決めたことと逆を勧める簡素化は指摘しない。行数・工数の減りだけを理由にしない（読む人が把握しやすくなるときだけ指摘する）。規約のファイルに書かれていない書き方・名前・設計の好みは指摘しない。
