## 完了報告のフォーマット

報告は**人が読むためのもの**で、`/loop` のための行を並べない。`/loop` の続行判断は、同じ会話に
残っているツールの結果（`tw ship` の先頭語と、送ったあとに取り直す `tw status`、判断待ちで外したなら `tw hold` の `CONTINUE`）から行う。

1. **結論を1文目に置く**: 送れたときは「`T-xxx <summary>` を完了して main へ送りました。」
   （`dropped` なら「`T-xxx <summary>` を見送って（dropped）main へ送りました。」と理由を1文）。
   `SHIPPED` の範囲・`branch=`・コミットのハッシュは書かない。手順8より前で止まったとき
   （`VERIFY_FAILED`・`CONFLICT`・`DIRTY`・取り残し・進められるタスクが無い、など）は、止まった
   ことと先頭語を結論にし、各手順の表が「添える」としたもの（パス・衝突したファイル・出力の末尾）を続ける
2. **何をしたか**を3項目程度の箇条書きで。変えたものと、それで何ができるようになったか・何が
   直ったかを1項目ずつ（ファイルの一覧やコマンドの経過ではなく中身を言う）
3. **人に知らせること**があるときだけ: 受け入れで直したこと、残した判断や気になった点（手順6aでドラフトに積んだ ID は、`report` の口があるときは `retrospective.drafts` に渡し、ここに書かない〔手順4〕。口が無いときはここに添える）、
   手順3でタスク化したなら登録したタスクID、`kept=` で枝を消せなかったこと
4. 検証コマンドの結果（件数。tw が補った `- 検証コマンド: 通過（…）` の行は件数が無いのでそのまま言う。「なし」なら完了条件を目視で確かめたこと。完了条件に印 `[目視]` の項目があれば、受け入れ役が見比べた画像と結果も）を1行で。
   手順6aの振り返りは、ツール一覧に `report` の口があるときは本文の節（`sections`）に書かず、`retrospective` 欄に渡す
   （口が無ければ、前と同じく `## 結果` の `- 振り返り:` の行そのままを1行で本文に書く）:
   `summary` は `## 結果` に入れた `- 振り返り:` の行の中身（1〜2文）、`drafts` は積んだドラフトのタスクID（積まなければ空の配列）。
   振り返りの段を通ったときだけ渡し、近道・並びから外したときなど通らなかったときは欄を渡さない（欄は任意で、無くても差し戻されない）
5. `/loop` で進められる行（取り直した `tw status` で `着手可否` が `READY` かつ `loopable` が `Y`）が
   無くなったときだけ1行: 未完了が残っていなければ「全タスク完了」、`HOLD`・`loopable: N` が
   残っていれば、その ID を添えて「残りは人の判断待ち」。

**構造の変更**: 委譲先の最後の段の返却にある `## 構造の変更` の行を、最終レポートの `graph` の `source` にそのまま写す
（記法は返却のとおり。`graph` の正典は tsukumo の `docs/architecture/display.md`）。`なし: <理由>` のときは `graph` を置かず、理由をレポートに添える。
節の中身は、各行が `+|-|~ A -> B` の形か、全体が `なし: <理由>` の1行で、`tw handback-guard` が本文を読める経路では、節が無い・空・形の違う返却を拒む。
`tw handback-guard` が本文を読めない経路で通った返却に節が無い・形が違うときは、受け入れの前に `SendMessage` で書き直させる。

同じ場面を撮った2枚（変更の前と後・差し色やキャラクター違い・幅違い）があれば、最終レポートの図は `image` を2つ並べず `beforeAfter` にする（左に前、右に後）。目視の画像の出どころは、受け入れ役の `- 目視:` の行で見比べた画像と、実装役の返却の変更前の画のパス。

書かないもの: 結論と重なる「完了したタスク」の行、
`tw status` の件数、`stale` の行
（これらは `tw status` を打てば人も見られる）。

**`/loop` の続行判断**（報告ではなく、会話に残ったツールの結果で決める）:

| 会話に残った結果 | 続行 |
| --- | --- |
| `tw ship` が `SHIPPED`・`NOTHING` で、取り直した `tw status` に `着手可否` が `READY` かつ `loopable` が `Y` の行がある | 続ける |
| `tw ship` が `SHIPPED`・`NOTHING` で、その行が無い | 続けない |
| `tw ship` がほかの先頭語か、判断待ちで外したとき以外で手順8より前で終わった | 続けない |
| 判断待ちで外し、`tw hold` が `CONTINUE\tY` を出し、作業ツリーに作業（`claim` した時点より後のコミットか変更）が無い | 続ける |
| `tw hold` が `CONTINUE\tN` を出したか、作業が残っている（次の `claim` が `DIRTY` で止まる） | 続けず、人の判断待ちを添えて終える |

判断待ちで外すのは、`tw ask-guard` に拒まれたときと、実装役が人の判断を要すると止めて返したとき（frame が実装と合わない等）。
論点を `tw hold T-xxx --reason-file -` に渡して外し、`loopable: N` には直さない（着手中の Y→N は `tw edit` が拒む）。
`report` の outcome は `stopped` でよいが、判断待ちで `report` の `favor` に判断のお願いを書く。

続行するときは、止めずに次の1件へ進む（文脈は Claude Code の自動の要約に任せる）。
