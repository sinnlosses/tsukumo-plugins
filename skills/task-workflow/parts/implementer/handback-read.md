5b. **返りを見る**（委譲先の hand-back か、Agent ツールの完了の通知が届くたびに。
   通知が「背景の作業を待っている」なら手順5dの1）。返却の種類で分ける。どの段の返却かは、メインが渡した段（並列の段では、返してきた担当に渡した段）で決める。止めたかは本文の先頭（brief の「段の進め方と返却」）で読む:

   | 返却 | すること |
   | --- | --- |
   | 書き直しから委譲した最初の返却（計画だけの回。委譲先は `phase_result` を呼ばない） | 下の表で計画を確かめる。段の数は、`tw plan-phases T-xxx --through 計画` の `delegatedRange.count`（Beads の `## やること` の段の数）で、その出力をそのまま `work_plan` に渡す。手順6へ進む行に当たれば、同じ委譲先へ `SendMessage` で「段1を進める」と渡す（下の表で打った `tw plan-check T-xxx` が `PARALLEL` を出したら、代わりに手順5の「並列の段」に従い、この委譲先を最初の担当にして待つ段の無い段を渡す） |
   | 渡した段 `n` を済ませた返却で `n` が段の数 `N` より小さい（先頭が `止めた:` などでない） | 受け入れはまだしない。同じ委譲先へ `SendMessage` で「段 <n+1> を進める」と渡し（差し戻して段 `n` をやり直させた返却は同じ段 `n` の返却として届くので、そのときは <n+1> を渡し直さず、差し戻しの前に渡していた次の段へ戻る）、次の返却を待つ（`N` が前の返却と違えば `tw show T-xxx` の `## やること` を読み直す）。並列の段では、`STEP` の行で段 `n` を待つ段のうち、待つ段がすべて返ったものを手順5の「並列の段」の割り当てで渡し、ほかの担当の返却も待つ。最後の段はほかの段がすべて返ってから渡す |
   | 渡した段 `N` を済ませた返却（最後の段。先頭が `止めた:` などでない） | 下の表へ |
   | 先頭が `止めた:`・`前提が誤り:`・`dropped にすべき:` の返却、または済んだとも止めたとも読めない返却（人の判断待ちは `hold` にして外し `/loop` を続ける。手順は同じ表の `止めた` の行） | `${CLAUDE_SKILL_DIR}/parts/implementer/return-abnormal.md` の表に従う |

   計画だけの回では、`tw plan-check T-xxx` を打ち、`tw show T-xxx` の `## やること` を読む。
   最後の段の返却では打たない（`tw accept` が手順6で `plan-check` を打つので、その `PLAN_*` の行を下の表で読む。
   `PLAN_REGISTERED` なら手順5と5bで `## やること` を見てあるので `tw show` も打たず、`PLAN_FIRST` のときだけ `tw show T-xxx` で読む）:

   | 見たもの | すること |
   | --- | --- |
   | `PLAN_REGISTERED`（計画どおりに委譲した）か `PLAN_FIRST`（書き直しから委譲した。`## やること` を作業より先に `tw edit` で書いた）で、`PLAN_UNCOVERED` が続かず（欄が無い旧い計画は出ないので `tw show` の `## やること` を読んで覆いを確かめる）、`## やること` が `## 完了条件` の各行を覆う | 最後の段なら手順6へ（差分が `## やること` と合うかは手順6で読む）。計画だけの回なら段1を渡す（`PARALLEL` が出ていれば手順5の「並列の段」に従って渡す） |
   | 上と同じで、`PLAN_UNCOVERED` が続く、または完了条件の行が `## やること` から抜けている | 最後の段なら、差分が抜けた行を満たしているかを手順6で読み、満たしていればメインが段を書き足して `tw edit T-xxx --section 'やること' --body-file -` で直す。計画だけの回なら、抜けた行を伝えて同じ委譲先に書き直させる |
   | 上のどれでもない | `${CLAUDE_SKILL_DIR}/parts/implementer/return-abnormal.md` の表に従う |
