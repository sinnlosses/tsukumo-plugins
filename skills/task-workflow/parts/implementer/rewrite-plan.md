# 書き直しから委譲する

手順5で「書き直しから委譲する」に当たったときの扱いと、メインが `## やること` を書いてよいときの条件。

## 書き直しから委譲する

   **書き直しから委譲する**: 依頼文は `tw brief implementer T-xxx` が `書き直し` の節で出す（文面は
   `${CLAUDE_SKILL_DIR}/parts/implementer/implementer-request.md` の `書き直し` の節。登録時の計画が古ければ
   `古い計画` の節が変わったファイルを添える）。`PLAN_REGISTERED` のまま書き直しに倒すときは `--rewrite` を付ける。
   書き直しの依頼は段を持たないので `--step` は付けられず、並列の段の節も入らない。計画だけの回は
   1匹で通し、メインが `## やること` を読んだあと段を渡すときから並列の段（手順5）にできる。

## メインが書いてよいとき

   **メインが書いてよいとき**: 「書き直しから委譲する」に当たり、同じセッションでこのタスクの設計を
   利用者と決めていて、`## やること` に要る正典・コードをメインがすでに読んでいるときだけ、
   メインが自分で `## やること` を書く（メインが新たに読み込みに行くなら委譲する。メインの文脈を
   膨らませない）。書いたら中身だけを `tw edit T-xxx --section 'やること' --body-file -` で渡し、
   `tw plan-check T-xxx` が `PLAN_FIRST` を返して `PLAN_UNCOVERED` が続かないこと（欄が無い旧い計画は
   出ないので、`## やること` が `## 完了条件` の各行を覆っているかを読む）を確かめる（足りなければ自分で
   `tw edit` を書き直す）。確かめたら「計画どおりに委譲する」。
