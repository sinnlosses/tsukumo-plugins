# 目視待ちの報告が来たとき

   **目視待ちの報告が来たとき**（描画を変えるタスクで、委譲先が組み立てた直後に返したもの。完了の
   hand-back ではないので、ここで受け入れを始めない）: メインは画像を開かない。受け入れ役を `目視待ち` の
   依頼で起こし（`tw brief acceptor T-xxx --visual-wait --image <報告の画像のパス>…`〔幅ごと。いちばん狭い幅も〕の出力の2行目以降を
   そのまま渡す。`acceptor-brief.md` の絶対パス・`## 完了条件` の目視の行・作業ツリーのパスが入る）、返却の `- 目視:` で分ける。`可` なら委譲先へ `SendMessage` で承認を返し
   （委譲先は期待値の撮り直しと `tw verify` に進む）、`否` なら `- 指摘:` の行をそのまま返して差し戻す。
   この受け入れ役は、最後の受け入れでも `SendMessage` で続けて使う。

## 完了条件に目視があるとき（手順6）

   **完了条件に目視（画面・見た目）があるとき**: `${CLAUDE_SKILL_DIR}/parts/acceptor/accept.md` の手順6の受け入れ役の依頼に、委譲先が報告した画像のパス
   （幅ごと。いちばん狭い幅も）を `tw brief acceptor` の `--image` で添える（`目視` の節が入る）。受け入れ役が最低1枚（いちばん狭い幅）を開いて `## 完了条件` の目視の行と
   1行ずつ見比べ、`- 目視: 可|否` を返す。**`可` になるまで手順7の `tw finish` に進まない**（`預ける` の返却でも `- 目視:` が `可` であることを確かめる。`否` なら `差し戻し` で返るはず）。
   `否` は `accept.md` の手順6の `差し戻し` と同じに委譲先へ返す。報告にパスが無い・開けないときも受け入れ役が `否` にして
   撮り直しを指摘に入れるので、そのまま委譲先へ渡す。見比べたパスと結果は受け入れ役の `- 目視:` の行を手順7の `tw finish` に渡す `## 結果` に写す。

## 実装の依頼文の目視の項目（手順5c）

   見本・目視・描画の変更があるタスクの実装の依頼文の項目は、`${CLAUDE_SKILL_DIR}/parts/implementer/implementer-request.md` の `目視` の節にあり、
   `tw brief implementer` が、完了条件に目視があるか `--visual` を付けたときに足す（`${CLAUDE_SKILL_DIR}/parts/implementer/delegate.md` の手順5c）。
