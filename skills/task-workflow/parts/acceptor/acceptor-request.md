# 受け入れの依頼文の型

`tw brief acceptor` が読み、場合に当たる節を選んで `{{名前}}` の値を埋め、受け入れ役へ渡す依頼文として出す型。
節の名前と、どの場合にどの節を選ぶか・値の中身は `tw brief --help` が持つ。最初の `## ` より前の行は出さない。

## 常に

タスク {{task_id}} の受け入れ。最初に {{here}}/acceptor-brief.md を読んで従う。
- 作業ツリー: {{worktree}}
- `tw show {{task_id}}` の `## 完了条件` の本文:

{{criteria}}

- プロジェクトの規約のファイル（そこから引かれるコーディング規約も読む）: {{rules}}
- `tw accept` の判定: {{verdict}}
- 振り返りの材料（委譲先の段ごとの返却の friction log の行、そのまま）:

{{friction}}

- `comment-audit` を Skill ツールで名前を指して読む（一覧の末尾が `comment-audit` の行。リンクで入れたとき
  `comment-audit`、plugin で入れたとき `tsukumo-workflow:comment-audit`。一覧に出ている名前のまま使う）。差分で足されたコメント行は、その置き場（Base directory）の
  `python3 <Base directory>/scripts/diff_added_comment_lines.py <下のコメント行の範囲>` で拾う

## 同じリポジトリ

- 差分を出すコマンド（作業ツリーで打つ）: `git diff HEAD` と、未追跡の新しいファイルを並べる `git ls-files --others --exclude-standard`
- コメント行の範囲: `HEAD`

## 別のリポジトリ

- 差分を出すコマンド（作業先の作業ツリーで打つ）: `git diff {{base}}...{{branch}}`
- コメント行の範囲: `{{base}}..{{branch}}`

## レビュー

- 1回目の木の SHA（2・3回目の差分の起点）: {{tree}}

## 目視

- 委譲先が報告した画像のパス（幅ごと。いちばん狭い幅も）。最低1枚（いちばん狭い幅）を開いて `## 完了条件` の画面・見た目を確かめる行と
  1行ずつ見比べ、`- 目視: 可|否` を返す。報告にパスが無い・開けないときは `否` にして撮り直しを指摘に入れる:

{{images}}

## 2回目以降

{{round}}回目の受け入れ。委譲先が前の回の指摘を直した。前の回に控えた木は {{since}}、いまの木は {{now}}。
`git diff {{since}} {{now}}`（作業ツリー {{worktree}} で打つ）で「前の指摘が直ったか」「直しが新しく壊したものがあるか」の
2つだけを見て、1回目と同じ形で判定を返す。コメント行を拾うコマンドも同じ2つの木（範囲 `{{since}}..{{now}}`）で打つ。
全差分への掛け直しはしない。
