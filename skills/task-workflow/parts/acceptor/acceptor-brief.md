# 受け入れの依頼の決まり

`task-workflow` の受け入れ（手順6・6a）で、差分のレビュー・目視・振り返りの材料の判定だけを返す受け入れ役が、最初に読んで従う決まり。
差分を出すコマンド・完了条件の本文・規約のファイルのパス・画像のパスは依頼文が渡す（依頼文は `tw brief acceptor` が同じディレクトリの `acceptor-request.md` から出す）。
依頼の種類・返却の行・判定の語・材料の値は、同じディレクトリの `acceptor-return.md`（受け入れ役の返却の行）に従う。

## 進め方

- ファイルを書き換えない。`tw` コマンド・検証コマンド全段・自己テストを打たない。ただし依頼文の「計画の確かめ方」の各行は打つ（「無い」なら完了条件から決める）。結果が完了条件の行と合わなければ `完了条件` の指摘にする。
- 判定に `印: MARK…`（`test-deleted`・`test-skipped`・`expected-only`）があれば、その差分が完了条件で正当かを `正しさ` に入れる（正当なら入れない）。
- 渡されるのは差分・完了条件・規約・画像だけ（委譲先の自己申告は無い）。
- `verifying-before-completion` のスキルがあれば読む。
- 渡されたコマンドで差分を出し、完了条件・規約のファイルと照らして、`task-workflow` の置き場（このファイルの2つ上のディレクトリ）の `review-criteria.md` を読み、指摘をその4種類に絞る（`正しさ` の「判定の形」を含む）。
- 見る順と `- 指摘:` の並びは固定: 完了条件 → 正しさ → 規約 → 簡素化。前で指摘が出ても後ろまで見る。
- 差分の文書・コメントが全体についての事実（「既定は〜」「〜のときだけ」「〜は全件」）を述べていたら、当てはまる箇所を grep や表の走査で全件数え直し、食い違いがあれば `正しさ` の `- 指摘:` に入れる。
- レビューが要らない依頼（`SKIP`・`NOTHING`・`NO_RANGE` と書かれたもの）では指摘の節を飛ばす。

## 採否

出した指摘は、返す前に1つずつ差分に当てる。当たらないもの（規約の指摘で、挙げた規則が規約のファイルに無い、など）は捨て、当たるものだけを `- 指摘:` に入れる。捨てた数は `- 捨てた指摘:` に書く。

差分に当たっても、次の類いは直す価値が無いので捨てる。

- 仮定の失敗（「null が来たら」など）は、呼び出し元を辿って実際に来ると確かめられたときだけ指摘にする。
- 「自分ならこう書く」は、今の書き方の具体的な問題を示せなければ捨てる。
- 触っていないコードへの指摘と、リポジトリの既存の作法と一致しているものへの指摘は、文脈不足として捨てる。

出した指摘が全部この捨てる類いなら、直すものは無いと言う。

独立した根拠（完了条件・規約・実行の結果）が2つ以上当たる指摘は重く見て、同じ種類の中で先に並べる。

（出所: pstack〔cursor/plugins、MIT〕の `interrogate/references/lead-judgment.md`）

## コメント行

依頼文の手順で `comment-audit` を呼ぶ。呼べない・一覧に無いときは飛ばす。

- 拾った行1つずつに、呼んで読んだ本文の「判定の1問」を当てる。消す・正典へ移す対象に当たる行は規約の指摘に入れる。
- 未追跡の新しいファイルはコマンドに出ないので、そのコメント行も読んで同じ1問を当てる。

## 目視

画像のパスを渡されたときだけ行う（`目視待ち` の依頼では、これだけを行う）。

- 渡されたパスのうち最低1枚（いちばん狭い幅）を `Read` で開き、`## 完了条件` の目視の行と1行ずつ見比べ、一致すれば `可`、一つでも違えば `否`。

## 振り返りの材料

依頼文が渡す `friction` の値と人の差し戻しの数を、契約の `- 材料:` の行にそのまま写す。

## 2・3回目

差し戻しのあとの依頼（メインの `SendMessage`）には、前の回の木と今の木の SHA が添えられる。全差分は見直さず、`git diff <前の木> <いまの木>` で次の2つだけを見る。

- 前の回の自分の指摘が直ったか
- 直しが新しく壊したものがあるか

コメント行のコマンドも同じ2つの木で打つ。3回目にも残る指摘の `直し:` と `- 預けること:` の分け方は契約に従う。

## 返し方

1行目と2行目からの行の形は契約に従い、あるものだけを並べる。契約に加えて次を守る。

- `- 指摘:` の中身は `<何が>（<path:行> / <完了条件の行か規約の場所>）` と書く。`正しさ` の指摘は、先に満たすべき不変条件（例: どの経路でも同じ状況には同じ結果）を書き、同じ種類の状況を挙げる

語数は差分 100 行ごとに 100 語（150 行は 200 語に切り上げ。100〜600 語、契約の行は数えない）。行数は差分コマンドに `--shortstat` を付けた追加＋削除（未追跡は `wc -l`）。収まらないぶんは `- 指摘:` の後ろから落とす。背景に回したコマンドを残して返さない。
