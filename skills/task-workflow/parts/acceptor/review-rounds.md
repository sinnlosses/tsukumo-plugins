# 差し戻しのあとの受け入れ（2・3回目）と、3回目にも指摘が残ったとき

手順6で受け入れ役が `差し戻し` を返し、委譲先が直したあとに受け入れを掛け直すとき（2・3回目）と、3回目にも指摘が残ったときの扱い。
3回目に `- 預けること:` が残れば `tw hold` で外して送らない。

## 2・3回目の受け入れ

   2・3回目の直前は、今までどおり個別に `tw lap T-xxx review start` を打ち（判定の直後は `tw lap T-xxx review end`）、
   `tw brief acceptor T-xxx --round <回> --since <前の回に控えた木>` を打つ。前の回の木は、1回目は `tw accept` の `SNAPSHOT` の行
   （別のリポジトリでは1回目の依頼文の木の SHA）、2回目からは前の回の `BRIEF` の行の末尾。tw が見る作業ツリーでいまの木を取り、
   `BRIEF` の行の末尾に出す（次の回の `--since` に控える）。

   **同じ受け入れ役に `SendMessage` で続けさせる**。受け入れ役は前の回の指摘と目視の基準を持っているので、
   原文は貼り直さない。渡すのは、その出力の2行目以降（前の回の木・いまの木・直した旨・2つの木で見る差分とコメント行の範囲）だけ。
   手順6で取り下げた指摘があるときは、その行も添える（委譲先の退けた案に当たったため。報告の本文は渡さない）。受け入れ役はそれを「前の指摘」に数えない。
   受け入れ役は「前の指摘が直ったか」「直しが新しく壊したものがあるか」の2つだけを見て、手順6と同じ形で判定を返す。
   全差分への掛け直しはしない。
   受け入れ役に `SendMessage` が届かない（呼び戻せない）ときだけ、新しい受け入れ役を起こし、
   前の回の指摘の原文（取り下げた行を除く）・2つの木の SHA・手順6の渡すものを渡す。

## 3回目にも指摘が残ったとき

   **3回目の返却にも指摘が残ったとき**は、メインは直さない。受け入れ役は、直し方が1つに決まる指摘に
   `直し: <どう直すか>` を添えて `- 指摘:` に入れ、直し方を選ぶ必要のある指摘を `- 預けること:` に入れて返す。
   判定は `${CLAUDE_SKILL_DIR}/parts/acceptor/accept.md` の手順6の表のとおり（`直し:` 付きが1つでもあれば `差し戻し`、`- 預けること:` だけなら `預ける`）。

   - `差し戻し`: `直し:` の付いた指摘を、メインが委譲先へ最後の差し戻しとして `SendMessage` で渡す（`正しさ` の指摘には、`accept.md` の手順6の `差し戻し` と同じ一文を添える。`簡素化` の指摘は、`accept.md` の手順6の取り下げの見方に当たるものを渡さない）。直ったあとはレビューを掛け直さず、
     手順6の `tw accept T-xxx --after-review` から順に進む
   - `- 預けること:` が1行でも残る（`差し戻し` に混ざったものも、`預ける` のものも）: 直さず、送らない。受け入れ役の行をそのまま
     `tw hold T-xxx --reason-file -` に渡して外し（`差し戻し` に混ざるときは、`直し:` の直しが済んだあと）、出力の `CONTINUE` で
     続けるかを決める（`${CLAUDE_SKILL_DIR}/completion-report.md` の続行判断）。手順7へは進まない。送るのは人が `todo` に戻してから
