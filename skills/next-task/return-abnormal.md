# 手順5bの返りの異常系

手順5bの表のうち、通常の返り（`PLAN_REGISTERED`・`PLAN_FIRST`）以外の行。並列の段の担当を起こしたときは、
`止めた <n>/<N>` はその段の担当にだけ当て、段 `n` を待つ段は渡さずに、ほかの担当の段は進める。
「前提が誤り」・`dropped` にすべき理由の報告はタスク全体に当て、ほかの担当を返却の切れ目で `TaskStop` で
止めてから表に従う。

   | 見たもの | すること |
   | --- | --- |
   | 「前提が誤り」の報告 | 手順7で `--dropped` にするか、`## 目的・背景` を直して手順4から着手し直すかを決める（直す `tw edit` には `--change-frame` を付ける。付けないと `FRAME_CHANGED` で拒まれる） |
   | `dropped` にすべき理由の報告 | 手順7へ（`--dropped`。理由を結果に書く） |
   | 1行目が `止めた <n>/<N>` | 理由を読み、メインで決められることなら決めて同じ委譲先へ `SendMessage` で段 `n` の続きを渡す。判断が `difficulty` を超えるなら手順5の「`difficulty` を上げるとき」で段 `n` から渡し直し、人の判断が要るなら理由を添えて人に預けて終了する |
   | 1行目が手順5bの頭の語（brief が指す契約の形）でない | 同じ委譲先へ `SendMessage` で、いま済んでいる段と、brief の形の1行目を尋ね直す（作業ツリーには触らない） |
   | `PLAN_NOT_FIRST`（`missing`・`after-work`・`unrecorded`・`steps`）か `PLAN_STALE` | `## やること` を作業より先に書かなかった。理由の語を一言メモしておく（手順6aの材料「受け入れでの直し」）。差分が完了条件を満たすなら活かして手順6へ進み、`## やること` はメインが差分から書き起こして `tw edit T-xxx --section 'やること' --after-work` で渡す。満たさなければ差分を退けて（自分の作業ツリー内の `git restore`）「書き直しから委譲する」で頼み直す |
   | 作業先の本体の作業ツリーに、委譲先の枝と同じ blob の未コミットの変更がある（手順6の「最初に本体の汚れを見る」） | 委譲先が本体を書き換えた。`SendMessage` で伝えて差し戻し、本体の変更が枝にもあることを確かめてから、そのファイルだけ `git restore` させる。委譲の前の控えにあった・枝と無関係なファイルは別の作業なので消さず、待つか人に預ける |
   | `NOT_OWNER` | 自分の作業ツリーの印が無い（人が `tw release --force` した、など）。ID を添えて終了する |
