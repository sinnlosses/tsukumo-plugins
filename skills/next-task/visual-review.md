# 目視待ちの報告が来たとき

   **目視待ちの報告が来たとき**（描画を変えるタスクで、委譲先が組み立てた直後に返したもの。完了の
   hand-back ではないので、ここで受け入れを始めない）: 報告の画像を最低1枚（いちばん狭い幅）`Read` で
   開き、`## 完了条件` の目視の行と見比べる。合っていれば `SendMessage` で承認を返し（委譲先は期待値の
   撮り直しと `tw verify` に進む）、合っていなければ何がどう違うかを返して差し戻す。差し戻したときは
   一言メモしておく（手順6aの材料「受け入れでの直し」）。

## 完了条件に目視があるとき（手順6）

   **完了条件に目視（画面・見た目）があるとき**: 委譲先が報告した画像のうち最低1枚（いちばん狭い幅）を
   `Read` で開き、`## 完了条件` の目視の行と1行ずつ見比べる。**見比べるまで手順7の `tw done` に進まない。**
   報告にパスが無い・開けない（置き場の一時ディレクトリが消えた、など）なら `SendMessage` で撮り直させる。
   報告の文字（「3幅とも一致・はみ出し 0px」など）だけで受け入れない。開いたパスは手順7の `## 結果` に書く。

## 実装の依頼文に足す項目（手順5c）

   - 「本文が見本（画・ラフ）のパスを名指していたら、最初にそれを開き、作った画面と見比べる。
     食い違ったら見本に合わせ、見比べた結果を報告に1行書く」
   - 「完了条件に目視（画面・見た目）があるタスクでは、撮った画像のパス（幅ごとに1行。いちばん狭い
     幅がどれかも書く）を報告に書く。画像は作業ツリーの外の、受け入れまで消えない場所に置く」
   - 「描画を変えるタスクでは、部品を差し替えて組み立てた直後に画を撮り、E2E の期待値の撮り直しと
     `tw verify` の前に、`tw pause` を打ってから画像のパスを書いた『目視待ち』の報告を返して止まる。メインが `SendMessage` で
     承認を返してから、期待値の撮り直しと `tw verify` に進む。差し戻されたら直して撮り直し、もう一度
     『目視待ち』で返す」
