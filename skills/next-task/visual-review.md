# 目視待ちの報告が来たとき

   **目視待ちの報告が来たとき**（描画を変えるタスクで、委譲先が組み立てた直後に返したもの。完了の
   hand-back ではないので、ここで受け入れを始めない）: メインは画像を開かない。受け入れ役を `目視待ち` の
   依頼で起こし（`acceptor-brief.md` の絶対パス・報告の画像のパス〔幅ごと。いちばん狭い幅も〕・`## 完了条件` の
   目視の行・作業ツリーのパスを渡す）、返却の `- 目視:` で分ける。`可` なら委譲先へ `SendMessage` で承認を返し
   （委譲先は期待値の撮り直しと `tw verify` に進む）、`否` なら `- 指摘:` の行をそのまま返して差し戻す。
   差し戻したときは一言メモしておく（手順6aの材料「受け入れでの直し」）。
   この受け入れ役は、最後の受け入れでも `SendMessage` で続けて使う。

## 完了条件に目視があるとき（手順6）

   **完了条件に目視（画面・見た目）があるとき**: 手順6の受け入れ役の依頼に、委譲先が報告した画像のパス
   （幅ごと。いちばん狭い幅も）を添える。受け入れ役が最低1枚（いちばん狭い幅）を開いて `## 完了条件` の目視の行と
   1行ずつ見比べ、`- 目視: 可|否` を返す。**`可` になるまで手順7の `tw finish` に進まない**（`預ける` の返却でも `- 目視:` が `可` であることを確かめる。`否` なら `差し戻し` で返るはず）。
   `否` は手順6の `差し戻し` と同じに委譲先へ返す。報告にパスが無い・開けないときも受け入れ役が `否` にして
   撮り直しを指摘に入れるので、そのまま委譲先へ渡す。見比べたパスと結果は受け入れ役の `- 目視:` の行を手順7の `tw finish` に渡す `## 結果` に写す。

## 実装の依頼文に足す項目（手順5c）

   - 「本文が見本（画・ラフ）のパスを名指していたら、最初にそれを開き、作った画面と見比べる。
     食い違ったら見本に合わせ、見比べた結果を報告に1行書く」
   - 「完了条件に目視（画面・見た目）があるタスクでは、撮った画像のパス（幅ごとに1行。いちばん狭い
     幅がどれかも書く）を報告に書く。画像は作業ツリーの外の、受け入れまで消えない場所に置く」
   - 「描画を変えるタスクでは、部品を差し替えて組み立てた直後に画を撮り、E2E の期待値の撮り直しと
     `tw verify` の前に、`tw pause` を打ってから画像のパスを書いた『目視待ち』の報告を返して止まる。メインが `SendMessage` で
     承認を返してから、期待値の撮り直しと `tw verify` に進む。差し戻されたら直して撮り直し、もう一度
     『目視待ち』で返す」
