# 委譲先の無応答に対応する

5a. **委譲先の無応答に対応する**（手順5で投げたあと、報告が来ないまま長く止まったとき。並列の段の
   担当を起こしたときは、担当それぞれに独立して当てはめる。ほかの担当が返していても、
   残りの担当の無応答は別に扱う）:
   1. **完了の通知が「背景の作業を待っている」で届いたら、待たずにその場で作業ツリーと成果物を見る**
      （通知を受けても放置し、人が指摘するまで気づかなかった実績がある）。
   2. **完了の通知だけが届いて返却（1行目が `計画 0/N`・`段 n/N`・`止めた n/N` の報告）が無ければ、
      段の進み具合を見て、同じ委譲先へ催促する**（同じセッションで2回、返却が届かず、
      メインが控えと差分を見て立て直した実績がある）。着手した作業ツリーの段 n の控え
      （名前と置き場は `skills/task-workflow/WORKFLOW.md` の `step` の行）の有無と、
      作業ツリー（作業先が別のリポジトリなら作業先の作業ツリー）の `git status` で見分ける:
      - 控えも差分も無ければ、段は未着手。
      - 差分だけがあれば、段は途中。
      - 控えがあれば、段は済んでいて返却だけが欠けている（最後の段は控えを打たないので、
        `tw verify-check` が `VERIFIED_SAME` かで見る）。

      催促は新しい委譲先を立てず、同じ委譲先へ `SendMessage` で「どこまで進んだか確かめて
      段 n を済ませて返す」と送る。催促しても返らないときは、次項以降の止め方・引き継ぎへ進む。
   3. **最後の書き込みから30分ほど動きが無ければ、作業ツリーに手を出さずに止める**（目安であって
      厳密な計測を求めない。進捗を尋ねても返らなかった実績が2件あるので、尋ねる段は必須にしない）。
   4. 止めたら最後の状態と `git diff` を読み、**完了条件を満たしていれば手順6で受け入れる**。
   5. 途中なら、済んだことと残りを明示して**別のサブエージェントに引き継ぐ**。`tw release` で
      捨てるのは差分が使えないときだけ。
