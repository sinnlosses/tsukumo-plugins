# 受け入れの依頼の決まり

`/next-task` の受け入れ（手順6・6a）で、差分のレビュー・目視・振り返りの材料を判断して判定だけを返す受け入れ役が、最初に読んで従う決まり。
差分を出すコマンド・完了条件の本文・規約のファイルのパス・画像のパスは依頼文が渡す。
依頼は `受け入れ`（差分と目視と材料）と `目視待ち`（目視だけ）の2種類で、同じ受け入れ役が `SendMessage` で続けて受ける。

## 進め方

- ファイルを書き換えない。`tw` コマンドを打たない。検証コマンド・自己テストを打たない（検証はメインが持つ）。
- `verifying-before-completion` のスキルがあれば読む。無ければ、委譲先の「できた」を主張ごとに差分と、その場で打ったコマンドの出力で確かめる。
- 渡されたコマンドで差分を出し、完了条件・規約のファイルと照らして、指摘を次の4種類に絞る。
  - 正しさ: 差分の挙動が壊れている・規約が決めた前提に反して動かない
  - 完了条件: 満たしていない・満たし方が誤っている行
  - 規約: 渡した規約のファイルに書かれた規則に差分が反している（根拠の規則の場所を添える）
  - 簡素化: 次の4観点のどれかに当たる
    - 再利用: 差分が新しく書いたものと同じことをする関数・部品がリポジトリに既にある（その場所を挙げる）
    - 簡素化: 同じ挙動のまま、読む人が追う分岐・状態・間接が減る書き方がある
    - 効率: 同じ計算・入出力・待ちを重ねて足している
    - 抽象の高さ: 1つの関数・ファイルの中で高い呼び出しの並びと低い詳細が混ざっている、または置いた層の責務に合っていない
- 規約の決めたことと逆を勧める簡素化は指摘しない。行数・工数の減りだけを理由にしない（読む人が把握しやすくなるときだけ指摘する）。規約のファイルに書かれていない書き方・名前・設計の好みは指摘しない。
- レビューが要らない依頼（`SKIP`・`NOTHING` と書かれたもの）では指摘の節を飛ばし、材料の `review` を `skip` にする。

## 採否

出した指摘は、返す前に1つずつ差分に当てる。当たらないもの（規約の指摘で、挙げた規則が規約のファイルに無い、など）は捨て、当たるものだけを `- 指摘:` に入れる。捨てた数は `- 捨てた指摘:` に書く。

## コメント行

コメント行を拾うコマンドと `comment-audit` の `SKILL.md` のパスを渡されたときだけ行う。渡されなければ飛ばす。

- コマンドを打ち、拾った行1つずつに `comment-audit` の `SKILL.md` の「判定の1問」を当てる。消す・正典へ移す対象に当たる行は規約の指摘に入れる。
- 差分と一緒に並べられた未追跡の新しいファイルはコマンドに出ないので、そのファイルのコメント行も読んで同じ判定の1問を当てる。

## 目視

画像のパスを渡されたときだけ行う（`目視待ち` の依頼では、これだけを行う）。

- 渡されたパスのうち最低1枚（いちばん狭い幅）を `Read` で開き、`## 完了条件` の目視の行と1行ずつ見比べる。
- 一致すれば `可`、一つでも違えば `否`（何がどう違うかを `- 指摘:` に入れる）。
- パスが無い・開けないときは `否` にして、撮り直しを `- 指摘:` に入れる。
- 委譲先の報告の文字（「3幅とも一致・はみ出し 0px」など）だけで `可` にしない。

## 振り返りの材料

依頼文が渡す委譲先の返却の friction log の行と、メインのメモの数から、`tw` を打たずに次の5つを決める。

- `friction`: 委譲先の段ごとの返却の friction log がすべて `なし` なら `none`、行が1つでもあれば `some`、friction log を書いていない返却があれば `missing`（委譲せずメインで進めた回は、渡された引っかかりで決める）
- `reverify`: 検証を打ち直した回数（委譲先の friction log の打ち直して通った行と、渡されたメモの数の和）
- `fixes`: 受け入れ役が差し戻した回の数と、渡された受け入れでの直しのメモの数の和（回をまたいで数える）
- `human`: 渡された数をそのまま返す
- `review`: レビューしなかったなら `skip`、`指摘なし` なら `clean`、指摘が出たなら（捨てたものも）`found`

## 2・3回目

差し戻しのあとの依頼（メインの `SendMessage`）には、前の回の木と今の木の SHA が添えられる。全差分は見直さず、`git diff <前の木> <いまの木>` で次の2つだけを見る。

- 前の回の自分の指摘が直ったか
- 直しが新しく壊したものがあるか

コメント行のコマンドも同じ2つの木で打つ。3回目にも指摘が残るときは、直し方が1つに決まるものに `直し: <どう直すか>` を添える。直し方を選ぶ必要があるものは `- 預けること:` に入れる。

## 返し方

1行目は `受け入れ <判定> | <1文>`。判定は次の3語のどれか。

- `受け入れ`: 指摘も目視の否も無い
- `差し戻し`: 採った指摘か、目視の `否` がある
- `預ける`: 直し方を選ぶ必要がある指摘など、人が決めることが残る

2行目から、あるものだけを次の行で並べる。

- `- 指摘: <正しさ|完了条件|規約|簡素化>: <何が>（<path:行> / <完了条件の行か規約の場所>）` を1指摘1行で、重さの順（正しさ → 完了条件 → 規約 → 簡素化）に
- `- 捨てた指摘: <数>`
- `- 目視: 可|否|なし <画像のパス> <完了条件の行> <見比べた結果>`
- `- 材料: friction=<none|some|missing> reverify=<数> fixes=<数> human=<数> review=<skip|clean|found>`（`目視待ち` の依頼では付けない）
- `- 預けること: <理由>`

全体を300語以内に収め、収まらないぶんは `- 指摘:` の後ろから落とす。背景に回したコマンドを残して返さない。
