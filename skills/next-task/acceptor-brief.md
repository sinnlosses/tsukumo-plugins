# 受け入れの依頼の決まり

`/next-task` の受け入れ（手順6・6a）で、差分のレビュー・目視・振り返りの材料を判断して判定だけを返す受け入れ役が、最初に読んで従う決まり。
差分を出すコマンド・完了条件の本文・規約のファイルのパス・画像のパスは依頼文が渡す。
依頼の種類・返却の行・判定の語・材料の値は、このファイルからの相対で `../task-workflow/WORKFLOW.md` の「受け入れ役の契約」に従う。

## 進め方

- ファイルを書き換えない。`tw` コマンドを打たない。検証コマンド・自己テストを打たない（検証はメインが持つ）。
- `verifying-before-completion` のスキルがあれば読む。無ければ、委譲先の「できた」を主張ごとに差分と、その場で打ったコマンドの出力で確かめる。
- 渡されたコマンドで差分を出し、完了条件・規約のファイルと照らして、同じディレクトリの `review-criteria.md` を読み、指摘をその4種類に絞る。
- 差分の文書・コメントが全体についての事実（「既定は〜」「〜のときだけ」「〜は全件」）を述べていたら、当てはまる箇所を grep や表の走査で全件数え直し、食い違いがあれば `正しさ` の `- 指摘:` に入れる。
- レビューが要らない依頼（`SKIP`・`NOTHING`・`NO_RANGE` と書かれたもの）では指摘の節を飛ばす。

## 採否

出した指摘は、返す前に1つずつ差分に当てる。当たらないもの（規約の指摘で、挙げた規則が規約のファイルに無い、など）は捨て、当たるものだけを `- 指摘:` に入れる。捨てた数は `- 捨てた指摘:` に書く。

## コメント行

コメント行を拾うコマンドと `comment-audit` の `SKILL.md` のパスは依頼文で渡される。渡されない呼び出し方のときは飛ばす。

- コマンドを打ち、拾った行1つずつに `comment-audit` の `SKILL.md` の「判定の1問」を当てる。消す・正典へ移す対象に当たる行は規約の指摘に入れる。
- 差分と一緒に並べられた未追跡の新しいファイルはコマンドに出ないので、そのファイルのコメント行も読んで同じ判定の1問を当てる。

## 目視

画像のパスを渡されたときだけ行う（`目視待ち` の依頼では、これだけを行う）。

- 渡されたパスのうち最低1枚（いちばん狭い幅）を `Read` で開き、`## 完了条件` の目視の行と1行ずつ見比べる。
- 一致すれば `可`、一つでも違えば `否`。
- パスが無い・開けないときは `否` にして、撮り直しを `- 指摘:` に入れる。
- 委譲先の報告の文字（「3幅とも一致・はみ出し 0px」など）だけで `可` にしない。

## 振り返りの材料

`tw` を打たず、依頼文が渡す委譲先の返却の friction log の行とメインのメモの数から、契約の材料の5つの値を決める。

## 2・3回目

差し戻しのあとの依頼（メインの `SendMessage`）には、前の回の木と今の木の SHA が添えられる。全差分は見直さず、`git diff <前の木> <いまの木>` で次の2つだけを見る。

- 前の回の自分の指摘が直ったか
- 直しが新しく壊したものがあるか

コメント行のコマンドも同じ2つの木で打つ。3回目にも残る指摘の `直し:` と `- 預けること:` の分け方は契約に従う。

## 返し方

1行目と2行目からの行の形は契約に従い、あるものだけを並べる。契約に加えて次を守る。

- `- 指摘:` の中身は `<何が>（<path:行> / <完了条件の行か規約の場所>）` と書き、重さの順（正しさ → 完了条件 → 規約 → 簡素化）に並べる。`正しさ` の指摘は、先に満たすべき不変条件（例: どの経路でも同じ状況には同じ結果）を書き、同じ種類の状況を挙げる

全体を300語以内に収め、収まらないぶんは `- 指摘:` の後ろから落とす。背景に回したコマンドを残して返さない。
