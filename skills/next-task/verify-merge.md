# 背景の検証に合流する（手順6b）

手順6で `tw verify` を背景で起こしたときだけ読む。背景の `tw verify` の完了を待ち（上限を付ける）、出力の最後の行で分ける。

| 最後の行 | すること |
| --- | --- |
| `VERIFIED`・`VERIFIED_UNSTAMPED` | 通った（取り込んだときは最後から2行目が `FOLDED`）。手順7へ |
| `VERIFY_NOT_PASSED`・`FORMAT_FAILED` | 手順6aのドラフトと `- 振り返り:` の行は捨てずに持ったまま、出力の末尾とログを読んで直し、`tw verify-check` → `tw verify`（今度は待つ）を打ち直す。振り返りはやり直さず、落ちて打ち直したことを `- 振り返り:` の行に足す |
| `CONFLICT` | 取り込みが衝突した（何も書き換えず、検証コマンドは打っていない）。手順8の `CONFLICT` と同じく、衝突したファイルを添えて人に預けて終了する（積んだドラフトは作業ツリーに残ることを添える） |
| `PLAN_MISSING` | `## やること` が空のまま作業がある（手順5bを通っていれば出ない）。差分から中身を書き起こして `tw edit T-xxx --after-work` で渡してから `tw verify` を打ち直す |
| `GIT_READ_ONLY` | 取り込みが要るのに `.git` に書けない（何も書き換えず、検証コマンドは打っていない）。sandbox の外で `tw verify` を打ち直す。打ち直せなければ、行を添えて行の3列目の次の一手を案内し、人に預けて終了する |
