# 受け入れの依頼文の型

`tw brief acceptor` が、場合に当たる節を選んで `{{名前}}` を埋め、受け入れ役への依頼文として出す型。
節の選び方と値は `tw brief --help` が持つ。最初の `## ` より前は出さない。

## 常に

`tw` を打たない（`tw verify-check`・`tw verify` もメインが確かめる）。判定に要る出力はこの依頼文のものを読んで判定だけを返す。
ファイルは書かない。一時ファイルが要るときも、書き先を変数にせず、絶対パスのリテラルで `Write` する。
タスク {{task_id}} の受け入れ。最初に {{here}}/acceptor-brief.md を読んで従う。
- 作業ツリー: {{worktree}}
- `tw show {{task_id}}` の `## 完了条件` の本文:

{{criteria}}

- 計画の確かめ方（完了条件の行ごと。打って結果を判定に使う）: {{how}}
- プロジェクトの規約のファイル: {{rules}}
- `tw accept` の判定と印（`MARK`: テストの削除・skip・期待値だけの差分）: {{verdict}}
- `friction` の値（`tw brief` が決めた1語）: `{{friction}}`

- `tsukumo-workflow:comment-audit` を Skill ツールで読む。差分で足されたコメント行は、その置き場（Base directory）の
  `python3 <Base directory>/scripts/diff_added_comment_lines.py <下のコメント行の範囲>` で拾う

## 同じリポジトリ

- 差分を出すコマンド（作業ツリーで打つ）: `git diff HEAD` と、未追跡の新しいファイルを並べる `git ls-files --others --exclude-standard`
- コメント行の範囲: `HEAD`

## 別のリポジトリ

- 差分を出すコマンド（作業先の作業ツリーで打つ）: `git diff {{base}}...{{branch}}`
- コメント行の範囲: `{{base}}...{{branch}}`

## レビュー

- 1回目の木の SHA（2・3回目の差分の起点）: {{tree}}

## 文書

文書だけの差分（`SKIP docs-only`）。指摘は `完了条件` だけ（`正しさ`・`規約`・`簡素化` は飛ばす）。
文書を上の `## 完了条件` と下の `## やること` の各行に照らし、外れた所を指摘する。

{{steps}}

## 2回目以降

{{round}}回目の受け入れ。委譲先が前の回の指摘を直した。前の回に控えた木は {{since}}、いまの木は {{now}}。
`git diff {{since}} {{now}}`（作業ツリー {{worktree}} で打つ）で「前の指摘が直ったか」「直しが新しく壊したか」の
2つだけを見て、1回目と同じ形で判定を返す。コメント行も同じ範囲 `{{since}}..{{now}}` で拾う。
